# Natural-response SOM behavior atlas contract

The Explorer reads a `sycophancy-som-behavior-atlas-v1` JSON file and matching receipt from `research_outputs/atlases/<id>/`. It never runs a model. The format is distinct from both teacher-forced atlas schemas. Only include observed natural-response activation maps and actual free-generation results. Do not copy scripted-response likelihood metrics into this format.

`atlas.json` has exactly these top-level fields: `schema`, `id`, `title`, `metadata`, `provenance`, `coverage`, `groups`, `maps`, and `behavior`. The installation ID must match `id`. `receipt.json` has exactly `schema`, `id`, `atlas_sha256`, and `atlas_bytes`; its schema is `sycophancy-som-behavior-atlas-receipt-v1`, and its hash and byte length bind the exact UTF-8 JSON file. Preserve the original source data, capture and grading receipts separately; this receipt establishes artifact integrity, not scientific validity.

`metadata` contains `model`, `revision`, `device`, `source_status` (`model_assisted_provisional`), `status` and `not_established`, a nonempty list of caveats that explicitly mentions confirmation and non-inferiority. Status is `not_yet_measured` for no maps or results, `discovery_measured` for fitted maps and no behavioral result, or `behavior_measured` when at least one complete paired result has been graded. These are developmental results unless independent confirmation is explicitly documented elsewhere.

`provenance` contains `data_sha256`, `labels_sha256`, `capture_sha256`, and `code_sha256`, each a lowercase SHA-256 or null before measurement. All four are required once a map or behavioral result is reported. Hash immutable source snapshots and receipts, not only filenames. `coverage` contains nonnegative `planned`, `generated`, `graded`, `missing`, `ungraded`, and `families`: generated + missing = planned; graded + ungraded = generated; families <= generated. This coverage is for natural response records, not a count of hidden-state coordinates. Omitted results and ambiguous or missing grades must remain visible.

`groups` contains `{id,label,color}` objects, where color is a six-digit hex color. A group ID is a label category, not a neuron. Each map has exactly `id`, `layer`, `seed`, `rows`, `columns`, `fit_count`, `fit_family_count`, `reference_count`, `reference_family_count`, `quantization_error`, `topographic_error`, and `cells`. The layout is square, either 2 by 2 or 4 by 4, with 4 or 16 cells respectively. `fit_count` counts actual natural-response states used to fit the SOM, and `reference_count` counts the independently responding reference population used for directions. The corresponding family counts are distinct families. Quantization error is nonnegative and topographic error is in [0, 1]; either can be null when unavailable. Layer/seed pairs are unique.

Each cell has exactly `id`, `x`, `y`, `count`, `family_count`, `fit_count`, `fit_family_count`, `label_counts`, `scenario_counts`, and `source_counts`. Its support includes assigned discovery states, while fit counts identify the subset used for SOM fitting. Family counts are distinct within the cell. Each composition dictionary partitions `count`; label keys must be defined group IDs. Cell fit counts sum to the map's fit count. Counts are nonnegative and cannot exceed their corresponding totals. Never treat multiple branches from one family as independent families.

`behavior` is an array, empty until measurements exist. Each result is `{scenario,metric,baseline,som,paired}`. Each arm is `{eligible,success,other,ungraded,missing}`, with the last four counts summing to eligible. The baseline and SOM arms use the same eligible histories. `paired` is `{eligible,complete,families,estimand,delta,ci_low,ci_high}`. The estimand is `equal_family_mean_branch_difference`: compute the SOM-minus-baseline outcome difference within each family, averaging eligible branches within that family, then average equally across families. Intervals must resample families. `complete` counts paired graded branches and `families` counts contributing families. For zero complete pairs, all estimates must be null; otherwise delta must be finite in [-1, 1], and confidence interval endpoints must either both be null or be ordered finite values in [-1, 1]. Rates in each arm and family-weighted differences are distinct summaries.

An optional paired-statistics extension adds all four fields together: `baseline_rate`, `som_rate`, `planned_families`, and `conservative_bounds`. The rates use the same complete-pair, equal-family population as `delta`, which must equal their difference within numerical tolerance. Contributing families cannot exceed planned families, and planned families cannot exceed eligible cases. `conservative_bounds` is an ordered pair in [-1, 1], or null when unavailable. It describes ambiguity, missingness and truncation in the observed planned panel; it is not a population confidence interval or a non-inferiority certificate. The UI labels these bounds separately from the family-bootstrap interval and warns when the latter is [0, 0].

The `scenario` field is a display grouping ID. Ordinary installs use substantive scenario names. The paired pilot groups rows as `adjudicated`, `reviewer_a` and `reviewer_b`, with the substantive endpoint explicit in `metric`. These are grading sensitivities of the same two conditions, not additional intervention arms. The adjudicated rows are shown first; both original reviewer groups and all caveats remain inspectable in expandable sections.

There are exactly two arm keys, `baseline` and `som`. The view displays no success estimate when responses are not yet graded. Do not claim that null uncertainty, attractive maps, or successful execution establishes mitigation or preservation. Model-assisted grades and references remain provisional, and prior tuning exposure is not final confirmation.
